# Скрипты публикации медиа мероприятия

Здесь сохранены без изменения четыре вспомогательных скрипта, использованных при подготовке мероприятия. Они не запускаются приложением автоматически. В них есть пути и имя бакета конкретного развёртывания; перед повторным использованием проверьте их и входные файлы.

- `upload-batch.mjs` проверяет подготовленные WebP, загружает их в настроенное хранилище приложения и проверяет публичные файлы по SHA-256. Принимает путь к manifest и выходному отчёту. `QUIZ_APP_DIR` указывает корень установленного приложения (по умолчанию `/opt/initiation-quiz`); `DATA_DIR` должен указывать его рабочие данные. Использует сохранённые настройки S3, секретов в скрипте нет.
- `apply-media.py` сопоставляет группы и отчёт загрузки, меняет только `mediaUrl` и ревизию рабочего мероприятия. Без `--commit` транзакция откатывается; для `--commit` обязателен `--backup`. Аргументы описаны в `--help`. Запуск с `--commit` изменяет указанную базу.
- `check-browser.py` выполняет проверку превью через реальную админскую сессию на домене мероприятия. Читает локальный `.deploy-server.env` и отчёт `data/group-video-preparation/uploaded.json`; для участника подменяет ответ API только внутри тестового браузера. Требует Playwright. Это ручная проверка, не часть изолированного набора тестов.
- `contact-sheet.mjs` создаёт контактный лист из подготовленных MP4 и отчётов в `data/group-video-preparation/rendered`. Требует FFmpeg и Sharp; запускать из корня проекта.

`drive-manifest.json` содержит сопоставление публичных исходных видео и групп с таймингами. Для использования скопируйте его в `data/group-video-preparation/manifest.json`: пути `source/...` разрешаются относительно manifest. Персональных данных участников в нём нет.

Общий процесс загрузки и нарезки описан в [документации по анимациям](../../docs/group-video-gifs.md). Входные видео, рабочие отчёты и готовые GIF/WebP хранятся отдельно от Git в `data/` и Object Storage.
