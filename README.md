# Квиз на посвящении

Одно приложение: квиз с телефона, зрительское голосование, админка и экран результатов. Node.js 24+ и SQLite; Sharp обрабатывает изображения, AWS SDK отправляет их в Yandex Object Storage. Данные хранятся на сервере; перезапуск серверной службы не сбрасывает ответы и показанные баллы.

## Состав репозитория

Здесь сохранены исходники приложения, тесты, документация, конфигурации развёртывания, скрипты подготовки анимаций и мониторинга. База мероприятия с участниками и результатами, пароли, ключи, исходные видео и сгенерированные медиа в Git не включены. Клонирование репозитория не восстанавливает рабочую базу: для переноса нужны отдельно сохранённый каталог данных и настройки сервера.

Дополнительные скрипты публикации медиа: [tools/event-media](tools/event-media/README.md). Исторические превью на тестовых данных: [docs/previews](docs/previews/README.md). Отчёт [deploy/verification.json](deploy/verification.json) описывает проверки на момент развёртывания, а не текущее состояние сервера.

## Запуск

```sh
npm ci
node server/index.mjs
```

Порт по умолчанию — **3000**. Страницы:

- `http://localhost:3000/` — участник.
- `http://localhost:3000/admin` — админка.
- `http://localhost:3000/screen` — проектор.

Фиксированные данные администратора по умолчанию: **admin / quiz-admin-2026**. При необходимости их можно задать переменными `ADMIN_USER` и `ADMIN_PASSWORD` до запуска. Сервер слушает `0.0.0.0`; переменная `HOST` позволяет изменить адрес.

## Docker

```sh
docker compose up --build -d
```

Приложение доступно на порту **3000**. SQLite, загруженные изображения и ключ хранения секретов сохраняются в томе `quiz-data`.

Другой порт для Compose:

```sh
PORT=8080 docker compose up --build -d
```

В Dockerfile порт задаётся строкой `ARG PORT=3000`. Его можно изменить при сборке или переопределить при запуске:

```sh
docker build --build-arg PORT=8080 -t initiation-quiz .
docker run -d --name initiation-quiz -p 8080:8080 -v quiz-data:/app/data initiation-quiz
```

Либо используйте стандартный образ и `-e PORT=8080 -p 8080:8080`. Для обычного запуска вне Docker: `PORT=8080 node server/index.mjs`.

Каталог данных задаётся `DATA_DIR`, по умолчанию `./data`; в контейнере — `/app/data`. Сохраняйте его целиком, включая `secret.key`, при переносе сервиса. Он содержит SQLite, локальные изображения и ключ шифрования секретов Яндекс ID и Object Storage. Для публичного мероприятия настройте HTTPS на вашем сервере или обратном прокси, затем задайте публичный адрес в админке.

## Развёрнутый сервер

Основной адрес приложения — `https://posvyat2026.h4ck.me` (порт **443**): `/` — участник, `/admin` — управление, `/screen` — проектор. Доступ по `https://91.84.97.114` также сохранён. HTTP на порту **80** автоматически перенаправляется на HTTPS. На этом сервере используется Node.js 24 и служба systemd `initiation-quiz.service`; Docker остаётся отдельным поддерживаемым вариантом запуска.

- Код: `/opt/initiation-quiz`.
- Постоянные данные, изображения и ключ секретов: `/var/lib/initiation-quiz`.
- Настройки запуска и отдельный пароль администратора: `/etc/initiation-quiz.env`, доступен только root.
- Конфигурация службы: [deploy/initiation-quiz.service](deploy/initiation-quiz.service). Служба запускается от пользователя `quizapp` и включена в автозапуск.
- HTTPS обслуживает Caddy, служба `quiz-caddy.service`: [конфигурация сайта](deploy/Caddyfile), [служба](deploy/quiz-caddy.service). Приложение слушает только внутренний адрес `127.0.0.1:3000`.
- Для этого локального прокси в `/etc/initiation-quiz.env` задано `TRUST_PROXY=loopback`: лимит попыток входа учитывает IP клиента. При прямом запуске без прокси этот параметр не требуется.
- Доверенные сертификаты Let's Encrypt выпущены отдельно для домена и IP. Caddy автоматически продлевает оба; сертификат IP использует профиль `shortlived`. Для проверки и продления оставляйте порты 80 и 443 доступными. Сертификаты и ключ аккаунта сохраняются в `/var/lib/quiz-caddy`.
- Данные доступа для организатора сохранены локально в `.deploy-access.txt`; этот файл исключён из Git и Docker-контекста. Стандартный пароль из примеров на сервере не используется.

Команды на сервере:

```sh
systemctl status initiation-quiz
systemctl restart initiation-quiz
journalctl -u initiation-quiz -n 100 --no-pager
systemctl status quiz-caddy
systemctl reload quiz-caddy
journalctl -u quiz-caddy -n 100 --no-pager
```

При обновлении кода сохраняйте каталог `/var/lib/initiation-quiz` и файл `/etc/initiation-quiz.env`. Рабочее мероприятие и репетиция используют отдельные состояния.

В настройках Яндекс ID публичный адрес — `https://posvyat2026.h4ck.me`. В приложении Яндекса используйте Redirect URI `https://posvyat2026.h4ck.me/auth/yandex/callback`. Если раньше был указан IP, обновите Redirect URI в кабинете Яндекса. Начало входа через Яндекс с IP перенаправляется на домен, чтобы авторизация и callback использовали один адрес и общие cookies.

## Подготовка мероприятия

Рабочая база заполнена из списка организатора: 27 групп, 464 участника (463 с почтой), 27 вопросов и 27 иконок таблицы. Подгруппы с буквами объединены; 24 записи исключены по указанию организатора. Базовые баллы взяты из последней колонки итогов, сумма — 1081. Для таблицы подготовлены миниатюры флагов WebP до 384 пикселей: все 27 занимают около 686 КБ; оригиналы сохранены. Импорт оставляет мероприятие в подготовке и сохраняет репетицию и настройки Яндекс ID. Фото/GIF и названия работ для зрительского голосования задаются отдельно.

1. В разделе «Группы» добавьте номера, названия и описания карточек, отдельные изображения для таблиц и голосования. Для карточек поддерживается GIF.
2. В «Участниках» задайте ФИО, группу и, при необходимости, почту Яндекса. Сохранение выдаст индивидуальный код для входа. Копируйте его из формы; в хранилище остаётся только защищённый отпечаток кода.
3. В «Вопросах» создайте вопросы, четыре варианта и правильный ответ. Настройте порядок.
4. В «Баллах» задайте готовую базовую сумму задавальника и редактуры одним целым числом.
5. В «Настройках» задайте отсечение зрительских оценок, фон проектора и логотип. При запуске проверяется, что после отсечения останутся оценки.
6. После начала квиза состав и вопросы фиксируются. Почту и код существующего участника можно исправить. База редактируется до первого показа основной таблицы.

## Проведение

Управление вопросом: начать → закрыть → показать ответ → ожидание → следующий вопрос. После последнего вопроса завершите квиз и откройте зрительское голосование. Все переходы ручные, таймеров нет.

Первый ответ участника окончательный. При закрытии случайный неправильный вариант назначается только неответившим участникам, которые хотя бы раз входили в систему в этом режиме. Никогда не входившие не добавляют голосов. Правильный вариант должен получить строго больше голосов, чем любой другой. За победу группа получает 1,5; вниз округляется сумма за весь квиз.

В зрительском голосовании нужно оценить все чужие карточки от 1 до 10. Сохранённый набор изменить нельзя. Сервер вычисляет среднее каждой оценивающей группы, отбрасывает выбранное количество крайних средних с обеих сторон и складывает остальные. Непроголосовавшая группа даёт нули; они также участвуют в отсечении.

После закрытия голосования покажите зрительскую таблицу. Следующая кнопка открывает основную таблицу с базой и фиксирует базовые баллы. Для каждой группы нажмите кнопку прибавления квиза. Повторное нажатие не начисляет баллы снова. Зрительские оценки остаются отдельным зачётом.

На экране группа сначала подсвечивается, выражение «база + квиз» показывается 7 секунд, затем баллы с ускорением перетекают из добавки в сумму: `12+4 → 13+3 → 14+2 → 15+1 → 16+0`. От начала отсчёта 1 балл переносится за 1 секунду, 2 — за 2, 4 — за 3, 8 — за 4; полное время переноса положительной добавки `b` равно `1 + log₂(b)` секунд. После короткой паузы `+0` исчезает, строка занимает новое место и иконка слегка приглушается. Пока квиз не раскрыт, баллы серые; раскрытые суммы белые. Быстрые нажатия на разные группы воспроизводятся по очереди. Обновление страницы показывает уже подтверждённые суммы без повторного начисления. В режиме уменьшенного движения выражение также видно 7 секунд, затем сумма меняется без перебора чисел и перемещения строк.

Чтобы провести всё повторно, в разделе «Управление» нажмите **«Начать заново»** и подтвердите сброс выбранного мероприятия. Кнопка доступна после старта в рабочем режиме и в репетиции. Она удаляет ответы, результаты квиза, зрительские оценки и раскрытые результаты; экран становится пустым. Группы, участники, коды входа, вопросы, изображения, настройки и базовые баллы сохраняются. Их снова можно редактировать до нового старта. Вошедшие участники остаются в системе и возвращаются к экрану с именем и группой; счётчик вошедших сохраняется. Ответы и черновики оценок прошлого запуска не переносятся. После сброса нажмите «Начать квиз».

## API для пульта

Пульт может опрашивать `GET https://posvyat2026.h4ck.me/api/quiz/results` раз в две секунды без авторизации. Для репетиции добавьте `?env=rehearsal`.

```json
{"question":3,"ready":true,"groups":{"Б05-627":"r","Б05-631":"g"}}
```

`question` — номер текущего вопроса в настроенном порядке, начиная с 1; до начала квиза — 0. `g` означает правильный ответ группы, `r` — неправильный, включая ничью. После закрытия вопроса результаты ещё скрыты. Они появляются только по кнопке «Показать ответы» и остаются доступны до следующего вопроса. Пока результаты скрыты, ответ содержит `ready:false` и `groups:{}`. Ответы не кешируются; персональные данные и варианты ответов в эту ручку не входят.

## Репетиция

Выберите «Репетиция» в админке. В настройках можно создать демонстрационные данные с произвольным количеством групп или скопировать рабочую конфигурацию. Кнопка симуляции подаёт тестовые ответы на текущем этапе через ту же логику приёма и подсчёта.

Демо-коды: `demo-601-1`, `demo-601-2` и далее по номеру группы и участника. Вход репетиции — `/?env=rehearsal`, её экран — `/screen?env=rehearsal`. При копировании рабочих списков создаются отдельные коды репетиции. Коды можно обновить в разделе участников.

Рабочие данные, ответы и экран не меняются от действий в репетиции. Переключение режима в админке выбирает отдельное сохранённое состояние, а не сбрасывает настоящее мероприятие.

## Яндекс ID

Настраивается через «Настройки → Яндекс ID»: Client ID, Client Secret, публичный адрес и переключатель входа. Redirect URI вычисляется с путём `/auth/yandex/callback`. Секрет после сохранения не возвращается в интерфейс. «Проверить вход» запускает настоящую авторизацию и проверяет получение почты; тест не регистрирует участника.

На странице «ПОСВЯТ ФПМИ» Яндекс показан первым, на контрастной кнопке; вход по коду расположен ниже. Локальный SVG логотипа взят из [официального оформления Яндекс ID](https://yandex.ru/dev/id/doc/ru/codes/buttons-design). После входа шапку отделяет тонкая линия; при ожидании показаны «Ждём…» и случайный смайлик. При каждом новом открытии ожидания, обновлении страницы или повторном входе смайлик меняется без повтора предыдущего. Обычный опрос сервера и обновление настроек его не меняют.

Пошаговая инструкция: [настройка Яндекс ID](docs/yandex-id-setup.md). Настоящий вход с Яндексом проверяется после регистрации вашего приложения и размещения сайта. Без него остаётся вход по персональным кодам.

## Изображения и Object Storage

В «Настройки → Хранилище изображений» укажите бакет и статический ключ сервисного аккаунта, сохраните и проверьте подключение, затем включите загрузку в хранилище. Настройки общие для рабочего режима и репетиции. Ключи хранятся зашифрованными и не возвращаются в браузер. Проверка создаёт маленький файл, проверяет его чтение без авторизации и удаляет его.

Новые изображения обрабатываются при загрузке: иконки уменьшаются до 384 пикселей, карточки и логотипы — до 960. GIF сохраняет анимацию в WebP; для иконки используется первый кадр. Удаляются метаданные, ограничены число кадров, время обработки и размер результата. Максимальный исходный файл — 10 МБ, анимация — 600 кадров и 2 минуты; чрезмерно большие файлы отклоняются с пояснением.

После включения хранилища участники получают файлы прямо из Object Storage с длительным кешированием; изображения карточек подгружаются по мере приближения к ним при прокрутке. При отключённом хранилище новые обработанные файлы сохраняются локально. Если включённое хранилище недоступно, загрузка сообщает об ошибке. Старые изображения сохраняют свои адреса, автоматического переноса в бакет нет. Object Storage не является CDN.

Пошаговая инструкция: [настройка Object Storage и создание ключа](docs/yandex-storage-setup.md).

Подготовка карточек из видео: [нарезка фрагментов, GIF 30 FPS, MP4 и WebP](docs/group-video-gifs.md).

На рабочем сервере 17 октября 2026 года вручную перенесены в `posvyat2026` все 27 ранее использовавшихся иконок групп (685 920 байт). Ссылки в базе обновлены после проверки побайтного совпадения и публичного чтения; локальные оригиналы сохранены. На момент проверки в рабочем режиме и репетиции не осталось используемых локальных изображений. Подробности переноса и резервной копии — в [отчёте проверки](deploy/verification.json).
