# Implementation contract

Node.js 24+ built-in HTTP and SQLite server, buildless browser ES modules. Sharp handles raster uploads; AWS SDK signs Yandex S3 requests. All JSON mutations send Content-Type application/json. Errors: {error: Russian text}, HTTP 400/401/403/409/413/429/502. Success JSON. Cookies are HttpOnly same-origin. Server default port 3000, DATA_DIR defaults ./data.

## Pages

- / participant mobile app
- /admin admin laptop app
- /screen?env=production projector, env=rehearsal for test screen

## Environment

Admin APIs take ?env=production|rehearsal (default production). Admin-selected environment does not change production participants. Participant login body accepts environment (defaults production). Admin cookie separate from participant cookie. GET /api/participant is anonymous-safe and returns authenticated:false when logged out.

## Routes

- POST /api/admin/login {username,password}; default admin / quiz-admin-2026, environment overrides allowed. POST /api/admin/logout {}.
- GET /api/admin/state?env=... returns {environment,state,settings,groups,participants,questions,scores,stats,yandex,storage}. 401 if not admin.
- POST /api/admin/groups {id?,number,title,description,iconUrl,mediaUrl,baseScore}; create/update (id string). DELETE /api/admin/groups/:id. POST /api/admin/groups/order {ids:[all group IDs in desired voting order]}; exact permutation required, frozen after quiz start. Order is stored per environment in settings.votingOrder; missing order uses creation order, new groups append. Admin groups and participant voting cards follow this order; the participant’s own group is omitted. Projector ranking remains score-based.
- POST /api/admin/participants {id?,firstName,lastName,groupId,email,code?}; returns {participant,code} on creation or explicit code regeneration. POST /api/admin/participants/:id/code {} regenerates; DELETE /api/admin/participants/:id.
- POST /api/admin/questions {id?,text,options:[4 strings],correctIndex:0..3}; DELETE /api/admin/questions/:id. POST /api/admin/questions/order {ids:[all IDs in desired order]}.
- POST /api/admin/scores {groupId,baseScore} before baseLocked; integer.
- POST /api/admin/settings {trimCount?,background?,logoUrl?,yandexEnabled?,yandexClientId?,yandexClientSecret?,publicUrl?}. background: CSS hex color or transparent. trimCount nonnegative integer, frozen after start; safe at least one retained rating required before start.
- POST /api/admin/upload {data:base64,name?,purpose?:'icon|card|logo'} -> {url}. Actual bytes must decode as PNG/JPEG/GIF/WebP; MIME/name do not determine format. 10 MiB input, 80MP across all frames, max 600 frames / 120s animation. Sharp resizes icons to 384px (first frame), cards/logos to 960px, preserves animation otherwise, strips metadata, usually returns WebP (small clean GIF may remain GIF). Output max 2 MiB static / 6 MiB animated. One processing job; concurrent jobs receive429. Local /uploads/<uuid>.<ext> when storage disabled; when enabled, upload to https://storage.yandexcloud.net/<bucket>/quiz/<uuid>.<ext> with immutable one-year caching. Failures return502 without local fallback. Both local and Yandex URLs are accepted by group/branding forms; no arbitrary remote URLs. Existing images are not migrated.
- POST /api/admin/storage {enabled?,bucket?,accessKeyId?,secretAccessKey?} -> redacted storage settings. Global across environments, independent of event phase. Empty key fields preserve existing values; both keys encrypted at rest, never returned. Enabling requires saved credentials. Endpoint https://storage.yandexcloud.net and region ru-central1 are fixed by server. Config changes clear lastTest except enabled toggle.
- POST /api/admin/storage/test {} -> redacted storage settings with lastTest:{ok,message,at}. Checks saved credentials even while disabled: signed PUT of a unique tiny image, anonymous GET with exact byte validation, DELETE of only its probe. Network failures are reported in lastTest, not mistaken for successful checks. Does not overwrite concurrent config/OAuth edits.
- POST /api/admin/action {action,groupId?,runId?} -> {state}. Actions: start_quiz (setup→open first), close_question (open→closed with random wrongs), reveal_question (closed→reveal), wait (reveal→waiting), next_question (waiting→open next), finish_quiz (all questions revealed→quiz_finished), open_voting (quiz_finished→voting_open), close_voting (voting_open→voting_closed), show_audience (closed vote→display audience), show_main (audience→main and freezes base), reveal_group (once-only group quiz addition). Provided runId must match current generation, else 409; frontend always sends it. No reopening a question, undo, time limits or premature result leakage.
- POST /api/admin/action {action:'restart_event',confirm:true,runId} resets a started event in the selected environment to setup/blank, clears answers/results/ballots/reveals, unlocks roster/rules/questions/base, increments runId. Requires explicit confirmation and current runId; rejects already-setup or stale requests with 409. Keeps groups, participants (including codes/joined flags), questions, images, base scores, settings and sessions. Other environment unchanged. This resets the entire event, not an individual question.
- POST /api/admin/rehearsal {action:'seed',groupCount?:27,participantsPerGroup?:2} seeds ONLY rehearsal sample data, or {action:'copy'} copies production configuration to clean rehearsal; requires admin. {action:'simulate'} submits rehearsal answers/votes using real scoring logic for current phase. This endpoint never alters production.
- POST /api/login {code,environment?}; POST /api/logout {}.
- GET /api/participant returns {authenticated,environment,participant?,state,question?,answer?,groupResult?,voting?,branding,yandexEnabled}. state includes phase,currentQuestionId. question {id,text,options,correctIndex?} correctIndex ONLY in question_reveal. answer {optionIndex,automatic} or null, groupResult {counts:[4 ints],choice,won} ONLY reveal. participant {id,firstName,lastName,groupId,groupNumber}. voting {submitted,groups:[{id,number,title,description,mediaUrl}]} during voting, no other people's scores.
- POST /api/answer {questionId,optionIndex,runId}; immutable first answer per run; 409 duplicate/closed/stale run.
- POST /api/vote {ratings:{groupId:integer1to10,...all other groups},runId}; single final submission per run; 409 duplicate/closed/stale run, 400 missing/extra/self/invalid. Only submitted ballots count. Missing runId is treated as 0 for pre-upgrade clients; after any reset they must refresh to load the updated client.
- GET /api/display?env=... returns {stage:'blank|audience|main',background,groups:[{id,number,iconUrl,score,revealed,baseScore?}],revision,runId,revealOrder}. groups empty until published. baseScore and revealOrder (group IDs in operator click order) are available for the main table; revealOrder is empty otherwise. No headings/text in /screen. Scores use full precision for sorting, audience formats1decimal, main integer. Main score=base + quiz iff revealed. The projector queues each reveal: highlight, 7-second base+addition hold, accelerating transfer (12+4→13+3→14+2→15+1→16+0), disappearance of +0, rank movement, subtle icon dimming. Transfer reaches 1/2/4/8 points after 1/2/3/4 seconds; positive bonus b takes 1+log2(b) seconds. Zero skips counting; reduced-motion retains the 7-second hold and uses a static total transition. Base-only scores are gray; revealed totals white. Reload shows the confirmed state without replay; stage/run changes cancel pending animation.
- GET /api/quiz/results?env=production|rehearsal is public and intended for a console polling every 2 seconds. Returns exactly {question:number,ready:boolean,groups:{groupNumber:'r'|'g'}}. question is the current 1-based position in the configured question order, or 0 in setup. Before the operator reveals answers (including while a question is closed), ready=false and groups={}. After reveal, ready=true and every group appears: g for a strict correct majority, r otherwise, including ties/abstentions. Published results remain during waiting and after the quiz, until another question opens or the event is restarted. Cache-Control:no-store. Default environment is production regardless of cookies; invalid env returns400, non-GET405. No participant information or answer choices are exposed.
- GET /auth/yandex/start?environment=production (participant login), GET /auth/yandex/start?test=1 (admin test); callback /auth/yandex/callback. Return to / or /admin?yandex=...; admin state yandex includes redacted settings and last test result.
- GET /api/health -> {ok:true}.

## Object shapes

state={runId:number,phase:'setup|waiting|question_open|question_closed|question_reveal|quiz_finished|voting_open|voting_closed',currentQuestionId:null|string,started:boolean,displayStage:'blank|audience|main',baseLocked:boolean,revision:number}. Participant state also includes runId. Existing saved events default to runId=0; reset, rehearsal seed and rehearsal copy advance the generation. Draft rating storage is scoped by environment, participant and runId.

groups=[{id,number,title,description,iconUrl,mediaUrl,baseScore}], participants=[{id,firstName,lastName,groupId,email,joined:boolean}], questions=[{id,text,options,correctIndex,position}].

scores=[{groupId,baseScore,quizScore,quizRaw,totalScore,audienceScore,revealed,voterCount}], stats={answeredCount,joinedCount,participantCount,submittedCount,byGroup:[{groupId,answeredCount,participantCount,joinedCount}]}. settings={trimCount,background,logoUrl,votingOrder?:[group IDs]}; yandex={enabled,clientId,secretSet,publicUrl,redirectUri,lastTest}; storage={enabled,bucket,endpoint,region,publicBaseUrl,accessKeyIdSet,secretSet,lastTest}. Secrets never returned.

## Invariants

At close, persist a random WRONG option only for abstainers with joined=true (ever logged in to this environment, including those now logged out). Never-joined members add no votes. A first login after close does not backfill an answer; existing accepted answers remain counted. Group wins iff correct count strictly greater than each other count. Tie group choice is persisted random wrong. floor(1.5 * total wins) once on total. Audience: equal-weight group means, zeros for absent group, trim k each end, SUM remaining, display1decimal only. Main excludes audience. Group/question/member edits frozen after quiz start; credential email/code corrections can remain possible if group and identity unchanged. Base editable until show_main. Display reveal idempotent.

Frontend should poll relevant endpoint about1second, preserve dirty forms and rating drafts across updates (do not rebuild a form every tick). Use responsive dark UI, no external fonts/CDN. /screen FLIP transforms for changed positions, ResizeObserver/grid column-major layout, reduced-motion fallback. Frozen controls clearly disabled. Rehearsal badge only admin, not projector.
