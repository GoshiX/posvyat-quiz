# Мониторинг во время посвящения

Инструменты запускаются **локально** из `/home/goshix/quiz`. На сервер ничего не устанавливается, код приложения, база и настройки не изменяются. Автоматического исправления, перезапуска, деплоя, авторизации или отправки ответов нет.

- `tools/monitor_production.py` проверяет публичные API, запускает диагностический код через SSH и сохраняет локальные отчёты.
- `tools/production_probe.py` передаётся через стандартный ввод `python3 -`. Он читает `/proc`, systemd, журнал и SQLite. База открывается с `mode=ro`, `readonly_shm=1` и `query_only`; код приложения не импортируется. Для базы в WAL требуются уже существующие файлы `-wal` и `-shm` работающего приложения: при их отсутствии проверка сообщает недоступность метрик и не создаёт их. Удалённые файлы не создаются.

## Подключение

Один раз открыть SSH-соединение с уже проверенным ключом сервера:

```sh
ssh -MNf -S /tmp/quiz-monitor.sock \
  -o ControlMaster=yes -o ControlPersist=2h \
  -o ServerAliveInterval=30 -o ServerAliveCountMax=2 \
  -o StrictHostKeyChecking=yes \
  -o UserKnownHostsFile=/tmp/quiz-deploy-known-hosts \
  root@91.84.97.114
```

Пароль вводится в приглашении SSH. Скрипты его не содержат и не сохраняют. Файл `/tmp/quiz-deploy-known-hosts` уже содержит проверенный ключ этого сервера. Если файл отсутствует, нужно восстановить доверенную запись; отключать проверку ключа нельзя.

## Запуск

Разовая проверка:

```sh
python /home/goshix/quiz/tools/monitor_production.py --once
```

Наблюдение каждые 30 секунд до Ctrl+C:

```sh
python /home/goshix/quiz/tools/monitor_production.py --watch
```

Ограниченная серия из 20 проверок:

```sh
python /home/goshix/quiz/tools/monitor_production.py --watch --samples 20
```

`--json` выводит полный отчёт. `--interval` меняет интервал в пределах 15–3600 секунд. Скрипт не запущен постоянно самим фактом создания файлов. Терминал должен оставаться работающим; автоматических сообщений в чат нет.

Последний результат: `/tmp/quiz-production-monitor/latest.json`. История: `/tmp/quiz-production-monitor/history.jsonl`. Файлы локальные, создаются с правами 0600; место можно изменить через `--output`. Они содержат технические метрики и публичные адреса изображений, без имён, почт, кодов, секретов, cookies и сырых сообщений журнала. В терминале время московское, в JSON — UTC.

## Что проверяется

- Четыре GET за цикл: `/api/health`, `/api/participant`, `/api/quiz/results`, `/api/display`. TLS проверяется штатно; редиректы не выполняются, чтобы случайно не запустить OAuth.
- По одному HEAD иконки и анимации в S3 за цикл. Проверяемые группы чередуются. Содержимое файлов не скачивается; проверка HEAD подтверждает доступность, тип и размер, но не декодирование всех кадров.
- Состояние приложения и Caddy, PID, число автоматических рестартов, память служб и файловые дескрипторы.
- CPU, доступная память, диск, системная очередь процессов, установленные TCP-соединения на порту 443 и сетевые счётчики. HTTP/3 использует UDP и не входит в счётчик соединений. Скорость сети появляется со второго успешного замера; это трафик всего сервера, исключая loopback.
- Фаза, текущий вопрос, состав, число когда-либо вошедших, ответы на текущий вопрос, сохранённые бюллетени и раскрытые итоги. `validParticipantSessions` — действующие сессии, **не онлайн**. HTTPS-соединения тоже не равны количеству людей.
- Новые ошибки журнала. Первая выборка охватывает последние две минуты; следующие имеют небольшое перекрытие и удаление дублей по идентификатору записи. Выборка ограничена; при достижении лимита есть предупреждение. Обычная отмена запроса клиентом не считается аварией.

Нет точного RPS и общей доли ошибок запросов: для этого нужны метрики запросов, которые сейчас не включаются, чтобы сохранить конфигурацию прода. Эта проверка также не выполняет полноценный вход через Яндекс и не имитирует 500 пользователей.

## Интерпретация

- `OK`: выполненные проверки без замечаний.
- `WARNING`: медленный API, нехватка ресурсов, новые записи об ошибках или недоступность части измерений. Отказ SSH отдельно отмечается как потеря серверных метрик; он не означает автоматически падение сайта.
- `CRITICAL`: публичный API не возвращает ожидаемый результат, служба остановлена, ресурсы почти исчерпаны или замечена серьёзная ошибка.

Медленный ответ (>1500 мс), высокая загрузка CPU и расхождение API с этапом мероприятия требуют двух последовательных наблюдений в режиме `--watch`. В разовом режиме выводятся все замечания. Смена PID или этапа отмечается отдельно. Коды завершения разовой проверки: 0 — OK, 1 — предупреждения, 2 — критические замечания; Ctrl+C — 130. В ограниченной серии код относится к последнему замеру, прежние ошибки остаются в истории.

При проблеме сначала проверить свежесть `latest.json`, затем конкретную метрику и соседние замеры. Разрешение на мониторинг **не даёт разрешения менять прод**: никаких рестартов, сбросов мероприятия, изменений данных или деплоя без отдельного указания пользователя.

После завершения наблюдения закрыть соединение:

```sh
ssh -S /tmp/quiz-monitor.sock -O exit root@91.84.97.114
```
