# Настройка входа через Яндекс ID

Для квиза нужны Client ID и Client Secret приложения Яндекса. Их нужно сохранить в разделе «Настройки → Яндекс ID». Серверный вход реализован; для проверки с настоящим Яндекс ID нужны параметры вашего приложения и размещённый сайт.

## Адрес возврата

В настройках квиза есть поле публичного адреса сайта. Из него админка формирует Redirect URI с путём `/auth/yandex/callback` и предлагает скопировать его.

Например, для сайта `https://quiz.example.org` адрес возврата будет `https://quiz.example.org/auth/yandex/callback`. Это условный пример: при регистрации нужно использовать настоящий адрес сайта. Получить параметры приложения можно заранее, но проверить вход получится после размещения сайта.

## Получение параметров приложения

1. Откройте [создание приложения для авторизации](https://oauth.yandex.ru/client/new/id/) под аккаунтом организатора.
2. Укажите название сервиса, иконку и контактную почту.
3. Выберите платформу «Веб-сервисы» и внесите Redirect URI будущего сайта.
4. В доступах выберите «Адрес электронной почты» и завершите регистрацию. ФИО и группы квиз берёт из своих списков, остальные данные Яндекса ему не требуются. Порядок регистрации описан в [инструкции Яндекса](https://yandex.ru/dev/id/doc/ru/register-auth).
5. Откройте созданное приложение в [кабинете Яндекс OAuth](https://oauth.yandex.ru/) и скопируйте Client ID и Client Secret. Оба значения доступны в свойствах приложения, как указано в [документации получения токена](https://yandex.ru/dev/id/doc/ru/codes/code-url).

Если Яндекс показывает предупреждение о непроверенном сервисе, пройти верификацию можно из его кабинета. Такое поведение описано в [правилах регистрации](https://yandex.ru/dev/id/doc/ru/register-auth).

## Заполнение админки квиза

| Поле | Значение |
| --- | --- |
| Публичный адрес сайта | Настоящий адрес размещённого квиза |
| Redirect URI | Адрес, сформированный админкой; его копируют в настройки приложения Яндекса |
| Client ID | Идентификатор из свойств приложения Яндекса |
| Client Secret | Секретный ключ из свойств того же приложения |
| Вход через Яндекс | Включить после заполнения параметров |

Сохраните настройки. Секрет вводится в закрытое поле и затем отображается только как сохранённый. Редактировать серверные конфигурационные файлы для этих настроек не потребуется.

## Проверка после размещения

Заранее добавьте участника с нужной Яндекс-почтой в админке. Сравниваться будет основная почта аккаунта, возвращаемая Яндексом: API предоставляет её в поле `default_email` при выданном доступе к почте. [Описание данных аккаунта](https://yandex.ru/dev/id/doc/ru/user-information).

Запустите «Проверить вход», войдите нужным аккаунтом и разрешите доступ к почте. Проверка должна подтвердить возврат на сайт и получение адреса. Затем обычный вход участника должен открыть правильные ФИО и группу. Проверка не должна создавать новые записи или обходить подготовленный список.

Если вход не проходит:

- При ошибке адреса возврата сравните полный Redirect URI в админке и кабинете Яндекса.
- При ошибке параметров проверьте, что Client ID и Client Secret взяты из одного приложения. Ошибка `invalid_client` означает неверные параметры либо недоступное приложение. [Ошибки обмена кода на токен](https://yandex.ru/dev/id/doc/ru/codes/code-url).
- Если авторизация у Яндекса успешна, а квиз отказывает в доступе, проверьте почту в записи участника и выбранный аккаунт.

До завершения настройки Яндекса участники смогут входить по своим персональным кодам.
